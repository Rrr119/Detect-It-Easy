# Test samples

These fixtures exercise the PEzor and generic entropy/import rules without
executing the files:

| File | Expected result | Purpose |
| --- | --- | --- |
| `pezor-x64.exe` | `PEzor`, `x64` | PEzor wrapper built from upstream source for x86-64. |
| `pezor-x86.exe` | `PEzor`, `x86` | PEzor wrapper built from upstream source for x86. |
| `clean-mingw-x64.exe` | No packer result | Same compiler/linker layout and CRT imports, but no payload loader APIs. |
| `generic-packed-pe.exe` | `Generic entropy-packed PE` | Two-section synthetic PE with a high-entropy executable section and no imports. |

SHA-256:

```text
1bac189b6d1c995a1cb1617610d4127b8bbce80ffdbd928d8741c41f4caaaddb  clean-mingw-x64.exe
485dc91c9475ccf1dce41581746cfa9537edab204006a7ad9960299be6171ff7  generic-packed-pe.exe
3e9176fc74361c228cefea5b6c6354560b3bf5d64ed2437e3ff6feb27d1b8a15  pezor-x64.exe
83e7629101744ac150ec7a7c75ef073b5234d5a2391525a9fef042cc74b08bb9  pezor-x86.exe
```

`pezor-x64.exe`, `pezor-x86.exe` and `clean-mingw-x64.exe` are built with
`build_pezor_samples.sh` from [phra/PEzor](https://github.com/phra/PEzor).
The embedded payload is a harmless NOP/`xor eax, eax`/`ret` stub. The clean control is
compiled with the same target and flags so section layout alone cannot
distinguish it from the wrapper.

`generic-packed-pe.exe` is generated by `make_generic_packed.py`; it contains
randomized bytes only to provide a deterministic high-entropy section and has no
import table.

Run the API and rule tests with:

```sh
node tests/pe_api.test.js
```
